## 1. 작업 컨텍스트

### 배경
써리힐즈(방 2개, 화장실 1개, 총 4인 거주)는 매주 4개 구역(주방/화장실/공용공간/분리수거)을 4명이 로테이션으로 담당한다. 현재는 운영자가 매주 수동으로 당번표를 만들어 카카오톡 단체방에 공지하고 있으며, 공지가 없거나 늦으면 로테이션이 어그러지고, 사진 인증 여부도 추적이 안 되어 패널티가 유명무실해지는 문제가 있다.

실제로 최근 몇 주간 인증사진 미제출이 반복되어, "청소 당일 자정까지 미제출 시 다음 주 공용공간 추가"라는 페널티 규칙을 운영자가 단체방에 재공지한 바 있다 (→ 3장 공지문 템플릿 참조). 이 규칙은 지금까지 말로만 존재했고 실제로 추적·집행된 적이 없었다 — 이번 시스템의 핵심 동기 중 하나가 바로 이 페널티를 "유명무실하지 않게" 실제로 추적·자동 적용하는 것이다.

### 목적
1. 매주 월요일, 고정 로테이션 규칙에 따라 이번 주 당번표를 자동 계산하고 카카오톡에 바로 붙여넣을 수 있는 공지문을 생성한다.
2. 사진 인증 제출 여부를 마감시각 기준으로 자동 추적하여, 누락 없는 이력을 남긴다.
3. 연속 미제출이 임계치를 넘으면 페널티(구역 추가)와 경고문을 자동으로 적용·생성하여, 지금까지 유명무실했던 규칙을 실제로 집행되게 한다.

### 범위
- 포함: 로테이션 계산, 공지문 생성, 제출 여부 자동/수동 기록, 이력 누적, **연속 미제출 페널티(구역 재배정) 및 경고문 자동 생성·공지 포함**
- 제외: 카카오톡 자동 발송(API 연동 없음, 운영자가 수동 복사·붙여넣기), 사진 내용(청소 품질)의 자동 판별, 거주자 영구 교체(이사/신규 룸메이트) 시나리오의 자동화(드물게 발생 — 이번 범위에서는 운영자 수동 처리로 충분, 우선순위 낮음)

### 입력
| 항목 | 설명 |
|---|---|
| 거주자 명단 (로테이션 대상) | 고정 4명: 소현, 은영, 제이, 승미 |
| 운영자 | 로테이션 대상 4명과는 별개의 역할. 운영자는 당번을 맡지 않으며, 실행·확인·완료 입력을 전담 |
| 구역 명단 (확정) | 아래 4개 구역, 각 담당 내용 고정 |
| 로테이션 상태 | 지난주 순번 인덱스 + 마지막 실행 ISO 주차(중복 실행 방지용) |
| 페널티 카운터 | 인원별 연속 미제출 횟수 (제출 성공 시 0으로 리셋) |
| 마감시각 | 청소 당일 자정 + 10분 유예(기본값, 조정 가능) |
| 운영자 확인 입력 | 사진 확인 후 완료 처리할 이름 (정확히 일치하는 이름만 인식) |
| 실행 트리거 | 매주 월요일 07:00, 캘린더/알림앱이 운영자에게 알림 → 운영자가 직접 실행. 07:00 알림을 놓치면 08:00~10:00 사이 1회 재알림 |

**구역별 담당 내용 (확정)**
| 구역 | 담당 내용 |
|---|---|
| 🚿 화장실 | 변기 · 세면대 · 바닥(하수구 머리카락) · 거울 얼룩 |
| 🍳 주방 | 싱크대(음식물) · 건조대(식기류 정리) · 인덕션+환풍기 |
| 🛋️ 공용공간 | 거실 · 세탁실 · 복도(현관) · 주방 바닥 (4개 세부작업 — 페널티 시 분담 단위) |
| ♻️ 분리수거 | 재활용 · 일반쓰레기 배출 · 쓰레기통 닦기 · 쓰레기통 비닐(라이너) 교체 |

### 출력
| 항목 | 설명 |
|---|---|
| 주간 공지문 | 신규 설계 포맷 (카카오톡 복붙용, 3장 템플릿 참조). 페널티 대상자가 있으면 자동으로 경고 문구 포함 |
| 체크리스트 갱신 결과 | 이번 주 4명의 제출 상태(완료/미제출) |
| 누적 이력 | 주차별 제출 이력 (연속 미제출 횟수 파악용, 3개월 보관 후 상세 삭제·요약만 유지) |

### 주요 제약조건
- 카카오톡 API 미연동 → 모든 발송·업로드 확인은 운영자의 수동 행위를 전제로 한다
- 사진 품질(청소가 실제로 잘 됐는지)은 시스템이 판단하지 않는다 — 운영자의 육안 확인만 반영하되, **평상시에는 엄격한 사진 검증을 하지 않고 당사자의 "완료" 신고를 그대로 신뢰한다.** 운영자가 실제로 사진을 자세히 확인하는 시점은 이의제기(분쟁) 발생 시뿐이며, 이때 카카오톡 채팅방의 원본 사진·게시 시각이 유일한 근거 자료가 된다 (시스템은 사진 자체를 저장하지 않음)
- 로테이션은 "한 명씩 아래로 내려가고 맨 아래가 맨 위로" 규칙 고정
- 운영자는 로테이션 대상에 포함되지 않는다 (4인 거주자 = 소현/은영/제이/승미이며, 운영자는 이 4명과 별개의 관리 역할)
- 실행 자체도 크론잡 등 서버 상시 구동 없이, **캘린더/알림앱 알림 → 운영자가 그 시점에 직접 실행**하는 방식 (완전 자동 발송이 아님)
- 같은 ISO 주차 내 중복 실행 방지: 이미 이번 주차에 실행된 기록이 있으면 재계산하지 않고 기존 결과를 그대로 다시 보여준다 (로테이션 인덱스가 중복 실행으로 밀리는 사고 방지)
- state.json 손상/삭제에 대한 별도 백업·복구 장치는 두지 않는다 — 값 자체가 사람이 기억/재구성 가능한 수준이라 판단, 이번 범위에서는 우선순위 낮음

### 용어 정의
- **로테이션 인덱스**: 이번 주 순환 위치를 나타내는 정수값
- **제출 상태**: `완료` / `미제출` / `확인대기`(마감 전) 세 가지
- **확인대기 → 미제출 자동 전환**: 마감시각(자정 + 10분 유예) 지나면 시스템이 자동으로 상태를 `미제출`로 바꿈. 이후 운영자가 사진을 확인하면 수동으로 `완료`로 정정 가능
- **공지 상태**: `생성됨`(공지문만 만들어진 상태) / `발송완료`(운영자가 실제로 카톡에 올리고 확인 입력까지 한 상태) 두 가지. 붙여넣기 자체는 시스템 밖 행위라 자동 감지 불가 — 운영자의 짧은 확인 입력("공지 완료")으로만 전환됨. 이 확인이 없으면 다음 실행 시 "지난주 발송 미확인" 안내가 재노출되며, **최대 3회까지 반복 안내**하고 4회째부터는 안내를 중단하고 자동으로 `발송완료`로 간주한다 (강제 차단 아님, 무한 반복 방지 목적)
- **연속 미제출 카운터**: 인원별로 마감을 놓친 횟수를 연속으로만 집계 (한 번이라도 제때 제출하면 0으로 리셋). 3회 연속 미제출 시점에 페널티 발동
- **페널티**: 연속 3회 미제출 시, 다음 한 주간 해당 인원이 공용공간(거실/세탁실/복도/주방바닥) 4개 세부작업을 그 주 원래 공용공간 담당자와 절반씩(2개씩) 나누어 맡는다. 원래 자기 구역은 유지하지 않고 공용공간으로 대체된다. 페널티는 해당 한 주에만 적용되고 그다음 주는 자동으로 원래 로테이션으로 복귀하며, 페널티 발동과 동시에 카운터는 리셋된다
- **경고문**: 페널티 발동 시 그 주 정규 주간 공지문에 자동으로 포함되어 단체방에 공개되는 문구 (별도 개인 DM이 아니라 공지문 내 포함 — 투명성 우선, 운영자가 개별적으로 완충하지 않음)

## 2. 워크플로우 정의

```
[매주 월요일 07:00, 캘린더/알림앱 알림 수신]
        │
        ├─(운영자가 08:00~10:00 사이에도 미실행 시)─▶ [1회 재알림, 이후는 스킵 로그]
        ▼
[운영자가 알림 확인 후 직접 실행 명령]
        │
        ▼
⓪ 이번 ISO 주차에 이미 실행된 기록이 있는지 확인
   - 있으면 → 재계산 없이 기존 결과 재노출 (중복 실행 차단)
        │
        ▼
① 로테이션 상태 로드 (스크립트)
        │
        ▼
② 이번 주 인원-구역 매핑 계산 (스크립트, 결정론적)
   - 결원 신고가 있는 인원은 이번 주 스킵, 다음 순번자가 2주 연속 담당
   - 페널티 대상자(연속 미제출 3회)가 있으면 공용공간 세부작업을 기존 담당자와 반반 분담하도록 재배정
        │
        ▼
③ 지난주 체크리스트 마감 처리 (스크립트)
   - 마감시각(자정+10분 유예) 지난 '확인대기' 건 → '미제출' 자동 전환
   - 미제출자의 연속 미제출 카운터 +1 (제출자는 0으로 리셋)
        │
        ▼
④ 공지문 생성 (스크립트, 템플릿 치환) → 공지 상태 = '생성됨'
   - 페널티 대상자가 있으면 경고문 자동 포함
        │
        ▼
⑤ 운영자에게 공지문 + 지난주 체크리스트 요약 제시
   (지난주 공지가 아직 '발송완료' 확인이 안 됐다면 여기서 먼저 안내, 최대 3회까지만 — 4회째부터는 자동 '발송완료' 간주)
        │
        ▼
⑥ 운영자가 카카오톡에 수동 붙여넣기 (시스템 밖 행위)
        │
        ▼
⑦ 운영자가 "공지 완료" 입력 → 공지 상태 = '발송완료' + 타임스탬프 기록 (스크립트)

[주중, 수시로]
당사자가 카카오톡 단체방에 "청소완료" 글 + 사진 게시 (기존 채널, 시스템 밖 행위)
        │
        ▼
운영자가 이를 보고 → "OO 완료 처리해줘" 입력 (정확히 일치하는 이름만 인식, 오타/별명은 재입력 요청)
   - 평상시엔 사진을 정밀 검증하지 않고 그대로 신뢰
   - 이의제기가 들어오면 그때만 카톡 채팅방 원본을 사후 확인 (시스템은 사진을 저장하지 않으므로 채팅 로그가 유일한 근거)
        │
        ▼
체크리스트 상태 갱신 + 이력 누적 (스크립트)

[요청 시]
다른 거주자가 이력을 보고 싶다고 요청 → 운영자가 이력 요약을 공유 (상시 셀프 조회 권한은 부여하지 않음)
```

### LLM 판단 영역 vs 코드 처리 영역
이 워크플로우는 **대부분 결정론적 규칙**(순환 계산, 시간 비교, 템플릿 치환, 카운터 증감)으로 처리 가능하며, LLM의 자연어 판단이 꼭 필요한 지점은 제한적이다.

| 단계 | 처리 주체 | 이유 |
|---|---|---|
| ①②③④ (페널티 재배정·카운터 포함) | 스크립트 | 순수 계산/치환/시간비교/카운터, 판단 요소 없음 |
| 거주자 결원/교체, 명단 변경 요청 감지 | LLM (에스컬레이션) | 정형화되지 않은 예외 상황 |
| 이름 불일치(오타/별명) 발생 시 재입력 요청 문구 | LLM | 자연어로 정중하게 재입력 유도 |
| 공지문에 특이사항(예: "이번 주 승미 휴가라 순서 조정") 자연스럽게 삽입 | LLM | 자연어 생성이 필요한 유일한 지점 |
| 페널티 경고문의 어조(비난조가 되지 않도록) | LLM | 사실 전달 + 관계 유지를 함께 고려해야 하는 자연어 생성 영역 |

즉 에이전트는 평소엔 스크립트 실행 결과를 그대로 사용자에게 보여주는 역할에 가깝고, 예외가 발생했을 때만 자연어로 개입한다.

### 단계별 성공 기준 / 검증 / 실패 처리

| 단계 | 성공 기준 | 검증 방법 | 실패 시 처리 |
|---|---|---|---|
| ⓪ 중복 실행 체크 | 같은 ISO 주차 재실행 시 로테이션이 재계산되지 않음 | state.json의 last_run_iso_week 비교 | 기존 결과 재노출, 재계산 스킵 |
| ② 로테이션 계산 | 4명×4구역이 중복·누락 없이 1:1 매핑됨 (페널티 주간엔 공용공간만 2인 분담) | 스키마 검증 | 에스컬레이션 (로직 오류 가능성, 사람 확인 필요) |
| ③ 마감 자동 전환 + 카운터 갱신 | 마감시각(자정+10분) 지난 '확인대기'만 정확히 '미제출'로 바뀌고 카운터가 정확히 ±1 됨 | 규칙 기반(시간 비교) | 스킵 + 로그 (다음 실행 때 재확인) |
| ④ 공지문 생성 | 신규 포맷(구역/담당자/날짜 범위/페널티 경고 유무)과 100% 일치 | 규칙 기반 | 자동 재시도 (템플릿 재적용) |
| 운영자 완료 입력 반영 | 입력한 이름이 이번 주 명단과 정확히 일치 | 문자열 정확 일치 검증 | 자동 재입력 요청 (퍼지 매칭 없음) |
| ⑦ 공지 발송 확인 | 운영자의 "공지 완료" 입력이 있어야만 `발송완료`로 전환 | 규칙 기반 (명시적 확인 문구 존재 여부) | 스킵 + 로그 → 최대 3회까지 "지난주 발송 미확인" 재노출, 4회째부터는 자동 `발송완료` 간주 |
| 페널티 발동 판정 | 연속 3회 미제출 시에만 발동, 중간에 한 번이라도 성공하면 카운터 리셋 | 규칙 기반(카운터 비교) | 에스컬레이션 (카운터 로직 의심 시) |

## 3. 구현 스펙

### 폴더 구조
```
/sunnyhills-cleaning
  ├── CLAUDE.md
  ├── /.claude
  │   └── /skills
  │       ├── rotation-generator/
  │       │   ├── SKILL.md
  │       │   └── /scripts   (rotation.py)
  │       ├── checklist-tracker/
  │       │   ├── SKILL.md
  │       │   └── /scripts   (checklist.py)
  │       └── notice-formatter/
  │           ├── SKILL.md
  │           └── /scripts   (format_notice.py)
  ├── /output
  │   ├── state.json               # 거주자/구역 명단, 로테이션 인덱스, ISO 주차, 페널티 카운터
  │   ├── checklist_history.json   # 주차별 제출 이력 (3개월 보관 후 요약화)
  │   └── weekly_notice_YYYYMMDD.md
  └── /docs
```

### CLAUDE.md 핵심 섹션
- 시스템 목적 및 범위
- 실행 트리거 안내 (매주 월요일 07:00 캘린더 알림 → 운영자 수동 실행, 08:00~10:00 1회 재알림, 자동 발송 아님)
- 로테이션 규칙 정의 (순환 방향, 시작 기준, 운영자는 로테이션 미포함)
- 구역별 담당 내용 (확정본 참조)
- 마감시각 정의(자정+10분 유예) 및 자동 전환 규칙
- 운영자 입력 명령 형식 안내 (예: "은영 완료 처리해줘" — 정확히 일치하는 이름만 인식, 불일치 시 재입력 요청)
- **페널티 규칙**: 연속 3회 미제출 시 다음 한 주 공용공간 세부작업 반반 분담 + 경고문 자동 포함, 발동과 동시에 카운터 리셋, 해당 주 한정 적용 후 자동 복귀
- 예외 상황(결원/교체/순서 조정) 발생 시 에스컬레이션 기준 — 결원 시 해당 주 스킵, 다음 순번자가 2주 연속 담당
- 이력 보관 정책: 3개월 후 상세 삭제, 요약만 유지. 상시 공개 아님 — 거주자 요청 시 운영자가 요약 공유

### 에이전트 구조
**단일 에이전트**로 구성. 워크플로우 자체가 짧고 대부분 결정론적이라 서브에이전트로 분리할 실익이 없음 (컨텍스트 최적화 필요 없는 규모).

### 단계별 처리 방식
| 단계 | 처리 방식 |
|---|---|
| 중복 실행 체크 | 스크립트 (state.json의 ISO 주차 비교) |
| 로테이션 계산 (결원/페널티 반영) | 스크립트 (rotation-generator) |
| 마감 자동 전환 + 연속 미제출 카운터 | 스크립트 (checklist-tracker) |
| 페널티 발동 판정 | 스크립트 (checklist-tracker, 카운터==3 조건) |
| 공지문 생성 (경고문 포함) | 스크립트 (notice-formatter, 템플릿 치환) |
| 예외 상황 안내 문구 작성 / 경고문 어조 조정 | 에이전트(LLM) 직접 생성 |

### 스킬 목록

**rotation-generator**
- 역할: 고정 명단/구역을 규칙에 따라 한 칸씩 순환시켜 이번 주 매핑 산출. 결원 신고 시 해당 주 스킵 및 다음 순번자 2주 연속 처리. 페널티 대상자가 있으면 공용공간 세부작업(거실/세탁실/복도/주방바닥)을 원래 담당자와 2개씩 나누어 배정
- 트리거: 매주 당번표 생성 요청 시 (월요일 실행), 단 같은 ISO 주차 내 재실행은 차단

**checklist-tracker**
- 역할: 마감시각(자정+10분) 경과분 자동 '미제출' 처리, 인원별 연속 미제출 카운터 증감(제출 성공 시 리셋), 카운터==3 도달 시 페널티 플래그 기록, 운영자의 수동 완료 입력 반영(이름 정확 일치 검증), 주차별 이력 누적 저장(3개월 후 요약화)
- 트리거: 당번표 생성 시(마감 처리) + 운영자가 완료 처리를 요청할 때

**notice-formatter**
- 역할: rotation-generator의 계산 결과를 신규 카카오톡 공지 포맷(제목/구분선/이모지 포함)으로 변환, 페널티 플래그가 있으면 경고문 자동 삽입, 공지 상태를 `생성됨`으로 기록. 이후 운영자의 "공지 완료" 입력을 받으면 `발송완료`로 갱신 + 타임스탬프 기록 (최대 3회까지 미확인 재안내 후 4회째 자동 간주)
- 트리거: rotation-generator 완료 직후 (생성 시) + 운영자가 "공지 완료"라고 입력할 때 (발송 확인 시)

### 주간 공지문 템플릿 (신규 설계)

기존에 실제로 반복 사용되던 "매주 당번표" 포맷은 없었고, 공유받은 참고 자료는 규칙을 재공지한 1회성 특별 공지문뿐이었다. 이를 참고해 아래와 같이 신규 설계한다.

```
📋 이번 주 청소 당번 (MM/DD ~ MM/DD)

🚿 화장실: {담당자}
🍳 주방: {담당자}
🛋️ 공용공간: {담당자}
♻️ 분리수거: {담당자}

📌 마감: 청소 당일 자정까지 인증사진 제출
📌 미제출 시 연속 미제출로 기록되며, 연속 3회 시 다음 주 공용공간 페널티가 적용됩니다

{페널티 발동 시에만 아래 블록 자동 추가}
⚠️ {이름}님은 지난 3주 연속 미제출로 이번 주 공용공간 페널티가 적용됩니다.
   → 공용공간 세부작업을 {원 담당자}님과 나누어 진행합니다.

{결원/특이사항 있을 시 LLM이 자연스럽게 삽입}
```

- 상단 4줄(구역-담당자 매핑)과 마감 안내는 매주 고정 포맷으로 스크립트가 채운다
- 페널티 경고 블록은 페널티 플래그가 있을 때만 자동 삽입되며, 그 외 주에는 아예 표시되지 않는다
- 규칙 자체에 대한 긴 설명(왜 이 규칙이 생겼는지 등)은 최초 1회 공지로 이미 안내되었으므로, 매주 반복하지 않고 위와 같이 짧은 사실 고지만 반복한다

### 데이터 전달 방식
파일 기반. `/output/state.json`(로테이션 인덱스, ISO 주차, 명단, 페널티 카운터), `/output/checklist_history.json`(이력)에 상태를 지속 저장하고, 각 스크립트는 파일 경로를 주고받는다. 데이터量은 작지만 매주 갱신되는 상태값이므로 인라인 전달보다 파일로 유지하는 편이 안전하다.

### 주요 산출물 파일 형식
- `state.json` — JSON
  - 로테이션 인덱스, 거주자/구역 명단
  - `last_run_iso_week` (중복 실행 방지)
  - `penalty_counters`: { 이름: 연속 미제출 횟수 }
  - `notice_confirm_pending_count`: 발송완료 미확인 반복 횟수 (최대 3)
  - 이번 주 공지 상태·타임스탬프
- `checklist_history.json` — JSON (주차별 제출 상태 이력, 3개월 경과분은 요약만 유지하고 상세 삭제)
- `weekly_notice_YYYYMMDD.md` — 마크다운/텍스트 (카카오톡 복붙용, 위 템플릿 참조)

## 4. 향후 확장 여지 (참고용, 이번 범위 밖)
- 카카오톡 챗봇 API 연동 시 ④⑤⑥ 자동 발송 및 거주자의 직접 "완료" 셀프 신고 UI(버튼 등)로 전환 가능 — 현재는 운영자가 카톡 채팅방 게시물을 보고 수동으로 입력을 대신 해주는 방식
- 사진 첨부를 시스템에 직접 업로드하는 인터페이스가 생기면, AI 이미지 판별로 checklist-tracker 확장 가능하고, 이의제기 시 근거 자료도 시스템 내에 남길 수 있음
- 거주자 영구 교체(이사/신규 룸메이트) 시 로테이션·명단을 갱신하는 전용 명령/스킬 (현재는 발생 빈도가 낮아 운영자가 state.json을 직접 수동 편집하는 것으로 충분하다고 판단)
- state.json 백업/버전 관리 (현재는 복구 장치 없음 — 필요성이 커지면 git 버전 관리 등 도입 검토)
